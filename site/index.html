A new image format
for smaller, faster files.

Tedd.FIC is a lossless image format with .NET and JavaScript codecs. Across 5,000 selected images, the .NET FIC Fast encoder produced 24.6% fewer bytes than SkiaSharp PNG and used 53× less summed encode time under the measured eight-worker workload. The format includes a versioned container and optional EXIF metadata.

GET STARTED

Use TFIC from .NET or JavaScript

Supply interleaved RGB or RGBA bytes in row-major order. The decoder restores the original bytes and dimensions.

INSTALL
dotnet add package Tedd.FIC
ENCODE & DECODE
using Tedd.FIC;

byte[] file = Fic.Encode(rgb, width, height, 3,
    effort: FicEffort.Fast);
byte[] pixels = Fic.Decode(file,
    out int w, out int h, out int channels);
JAVASCRIPT · BROWSER OR NODE.JS
import { encode, decode } from './tfic.js';

// rgba is a Uint8Array, four bytes per pixel.
const file = encode(rgba, width, height, 4);
const { pixels, width: w, height: h, channels } = decode(file);

// Load a .tfic file from a URL:
const response = await fetch('image.tfic');
const loaded = decode(new Uint8Array(await response.arrayBuffer()));

The package currently targets .NET 11 preview. The JavaScript decoder accepts Fast and Compact streams from .NET and verifies CRC-32C. The JavaScript encoder writes interoperable Fast-tier literal strips; its output may be larger than the .NET encoder’s optimized output. View the JavaScript module →

FILE FORMAT

A container with room for metadata

Files start with TFIC, followed by a single version byte (00) and an EXIF length. The optional raw EXIF TIFF payload comes before the compressed image data. The pixel stream includes a CRC-32C checksum.

0–3TFIC
400
5–8EXIF length
9…EXIF data
next…Image payload

EXIF is preserved as bytes; the library does not interpret its tags. Read the container specification →
