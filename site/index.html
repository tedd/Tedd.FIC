Tedd.FIC is a lossless image format with .NET, TypeScript/JavaScript, C, and x86/x64 assembly implementations. Across 5,000 selected images, the .NET FIC Fast encoder produced 24.6% fewer bytes than SkiaSharp PNG and used 53× less summed encode time under the measured eight-worker workload. Optional Deflate, GZip, Zstandard, and Brotli compression can reduce FIC files further.

GET STARTED

Use FIC from .NET, TypeScript/JavaScript, C, or assembly

Supply interleaved RGB or RGBA bytes in row-major order. The decoder restores the original bytes and dimensions.

INSTALL
dotnet add package Tedd.FIC
ENCODE & DECODE
using Tedd.FIC;

byte[] file = Fic.Encode(rgb, width, height, 3,
    effort: FicEffort.Fast, compression: FicCompression.Auto);
byte[] pixels = Fic.Decode(file,
    out int w, out int h, out int channels);
JAVASCRIPT · BROWSER OR NODE.JS
import { encode, decode, decodeAsync } from './fic.js';

// rgba is a Uint8Array, four bytes per pixel.
const file = encode(rgba, width, height, 4, new Uint8Array(), 'Zstd');
const { pixels, width: w, height: h, channels } = decode(file);

// Load a .fic file from a URL:
const response = await fetch('image.fic');
const loaded = await decodeAsync(new Uint8Array(await response.arrayBuffer()));

The package targets .NET 11 RC1 or later. Auto uses no outer compression for Fast, Zstandard quality 2 for Default, and Brotli quality 5 for Max. Explicit Zstandard at Fast effort uses quality 1. Deflate, GZip, Zstandard, and Brotli are available at every effort. The JavaScript module encodes and decodes all four outer compression types without browser compression APIs. Its encoder writes Fast-tier literal strips and stores an uncompressed payload when the requested outer codec does not reduce its size. The TypeScript source builds the JavaScript module and type declarations.

Native source

C codec — a CMake build with a C API for encoding and decoding. Its encoder writes uncompressed version 00 files; compressed decoding uses a caller-supplied decompression callback.

32-bit x86 assembly and 64-bit x64 assembly — Windows assembly listings with a shared C interface and build script. Their encoders write uncompressed Fast-tier files; decoding compressed files requires a caller-supplied callback.

FILE FORMAT

A container with room for metadata

Version 02 records one compression byte, EXIF length, and expanded payload length. Compression byte values are 0 = none, 1 = Deflate, 2 = GZip, 3 = Zstandard, and 4 = Brotli. Raw EXIF TIFF bytes come before the image payload; the pixel stream includes a CRC-32C checksum. Versions 00 and 01 remain readable.
